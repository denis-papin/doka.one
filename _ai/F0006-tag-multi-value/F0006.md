# Goal
Add a new tag type **`Multi`** that holds a **set of values drawn from a
predefined vocabulary**, with four set-algebra filter operators (`ANY`, `ALL`,
`NONE`, `IS`) supporting `%`/`_` wildcards. Example tag: `color` with
`predef_values = {BLUE, GREEN, RED, YELLOW}` and item values like `{RED,BLUE}`,
`{}`, `{GREEN}`. A typical filter: `(color ANY [G%, RED])`.

# Gap
`tag_definition.type` supports scalar types only (`Text`, `Int`, `Bool`,
`Double`, `Date`, `DateTime`, `Link`). There is no way to attach a *set* of
chosen-from-a-list values to an item; users wanting "topic chips", "status
flags", "color labels" have to fake it with concatenated strings or by creating
N boolean tags. The filter pipeline (`filter_ast` → `type_resolver` →
`generator`) has no list literal and no set operators. `tag_value` has no
column suitable for a set.

# Inputs
- **Tag definition (creation)**: `type = "Multi"`, plus a non-empty
  `predef_values: Vec<String>` carrying the bounded vocabulary
  (e.g. `["BLUE","GREEN","RED","YELLOW"]`).
- **Item tag value (write)**: a list of strings, each member of the tag's
  vocabulary. Order and duplicates are not significant. Empty set is allowed.
- **Filter**: `(<attribute> <op> [<elt>, <elt>, …])` where `<op>` ∈
  `{ANY, ALL, NONE, IS}` and each `<elt>` is either a literal vocabulary value
  (e.g. `RED`) or a SQL-LIKE pattern (`%`/`_`, e.g. `G%`).

# Output
- `tag_value.value_multi text[]` holds the set, **normalized** (sorted +
  deduped) at write time.
- Search SQL keeps today's JOIN-per-tag shape — one row per `(tag_id, item_id)`
  is preserved, so no `DISTINCT`, no `EXISTS`, no plan reshape. The predicate
  in the `WHERE` is one of `&&`, `@>`, `NOT (… && …)`, `=`.
- `TagValueElement` (read) exposes the set as `Vec<String>`.

# Architecture — three layers of change

| Layer       | Change                                                                                  | Module / file                                                  |
|-------------|-----------------------------------------------------------------------------------------|----------------------------------------------------------------|
| Schema      | New column `value_multi` on `tag_value`; new column `predef_values` on `tag_definition`; GIN index on `value_multi`. **Unique index `tag_value_tag_item_udx` stays.** | `admin-server/resources/schema_cs.ddl`                         |
| DTO + parser| New `EnumTagValue::Multi(Vec<String>)`; new `FilterValue::ValueList(Vec<String>)`; new operators `ANY`, `ALL`, `NONE`, `IS` in the lexer/parser; `predef_values` on tag DTOs | `dkdto/src/web_types.rs`, `filter/filter_ast.rs`, lexer        |
| Resolver + SQL gen | Validate operator/type pairings; expand wildcards against `predef_values` at compile time; emit one set-predicate SQL fragment per leaf | `filter/type_resolver.rs`, `engine/generator.rs`, `document-server/src/item.rs`, `document-server/src/tag.rs` |

# Rules

1. **Schema (`schema_cs.ddl`).**
   ```sql
   ALTER TABLE tag_definition ADD COLUMN predef_values text[];
   ALTER TABLE tag_value      ADD COLUMN value_multi  text[];
   CREATE INDEX tag_value_multi_gin_idx ON tag_value USING gin (value_multi);
   ```
   `value_multi` is NULL for non-`Multi` tags; `predef_values` is NULL for
   non-`Multi` tags and **NOT NULL with `array_length ≥ 1`** when
   `type = 'Multi'` (enforced in the Rust write path; no CHECK constraint).
   The unique index `tag_value_tag_item_udx (tag_id, item_id)` is **kept**: one
   row per `(tag, item)` remains the invariant.

2. **New `EnumTagValue` variant** (`dkdto/src/web_types.rs`):
   ```rust
   pub enum EnumTagValue {
       Text(Option<String>), Boolean(Option<bool>), Integer(Option<i64>),
       Double(Option<f64>), SimpleDate(Option<String>), DateTime(Option<String>),
       Link(Option<String>),
       Multi(Option<Vec<String>>),  // NEW
   }
   ```
   `TagElement` (response) gains `pub predef_values: Option<Vec<String>>`.

3. **Write-time normalization** (in `create_item_property` /
   `change_item_tag_value` in `document-server/src/item.rs`):
   - Validate every element belongs to the tag's `predef_values`; reject with
     `BAD_TAG_FOR_ITEM` otherwise.
   - Sort ascending + dedup → store the canonical form in `value_multi`.
   - This canonicalization is what makes `IS` cheap (plain `=`).

4. **Filter language additions.**
   - New value shape `FilterValue::ValueList(Vec<String>)`, syntax
     `[ELT_1, ELT_2, …]` where each `ELT` is either an unquoted literal
     vocabulary code or a double-quoted pattern containing `%` or `_`.
   - New operators `ANY`, `ALL`, `NONE`, `IS`.
   - `LEGAL_OPERATORS_BY_TAG_TYPE`: `TagType::Multi → {ANY, ALL, NONE, IS}`.
     All other types reject these operators; `Multi` rejects all other operators.

5. **Compile-time wildcard expansion** (in `type_resolver`):
   For each list element of an `ANY` / `ALL` / `NONE` clause:
   - If it contains `%` or `_` → expand against the tag's `predef_values` using
     SQL-LIKE matching, yielding a (possibly empty) subset.
   - Literals are validated against `predef_values` and pass through as a
     1-element subset.
   - `IS` does **not** accept wildcards — reject with
     `INVALID_FILTER_FOR_TAG_TYPE`.

6. **Operator → SQL mapping** (in `generator.rs::build_tag_value_filter`,
   new arm `TagType::Multi`):

   | Operator | Compile-time shape                                  | Emitted SQL fragment                                                      |
   |----------|-----------------------------------------------------|---------------------------------------------------------------------------|
   | `ANY`    | union all expansions → one set                      | `tv.value_multi && ARRAY[<set>]::text[]`                                  |
   | `NONE`   | union all expansions → one set                      | `NOT (tv.value_multi && ARRAY[<set>]::text[])`                            |
   | `ALL`    | one expansion per element (each must overlap)       | `tv.value_multi && ARRAY[<exp_1>] AND tv.value_multi && ARRAY[<exp_2>] …` |
   | `IS`     | literal set, sorted + deduped                       | `tv.value_multi = ARRAY[<set>]::text[]`                                   |

   Outer query shape is unchanged from today (single JOIN per tag).

7. **Static short-circuits in the resolver** (before SQL emission):

   | Situation                            | `ANY`                | `NONE`                | `ALL`                                | `IS`              |
   |--------------------------------------|----------------------|-----------------------|--------------------------------------|-------------------|
   | A pattern expands to `∅`             | clause → `FALSE`     | clause → `TRUE` (drop)| clause → `FALSE`                     | n/a (no wildcards)|
   | A pattern expands to full vocabulary | drop clause          | clause → `IS []`      | element → "non-empty" check          | n/a               |
   | Literal list `[]`                    | `FALSE`              | `TRUE` (drop)         | `TRUE` (drop)                        | empty-set match   |

   When the whole filter becomes static `FALSE`, return 0 rows without hitting
   the DB.

8. **Backward compatibility.** `Text` / `Int` / `Bool` / `Double` / `Date` /
   `DateTime` / `Link` paths are untouched. The unique index on `tag_value` is
   preserved. No migration logic for existing tags. The persistence layer
   (`persist_compiled_query`) needs no change beyond the new operator strings
   appearing in the SQL text.

# Errors

| Condition                                                                                  | Stage that rejects             | Outcome                                  |
|--------------------------------------------------------------------------------------------|--------------------------------|------------------------------------------|
| Create a `Multi` tag with empty/missing `predef_values`                                    | `add_tag` (`tag.rs:356`)       | 400 — `BAD_TAG_DEFINITION`               |
| Write a `value_multi` containing a value outside `predef_values`                           | `create_item_property` / `change_item_tag_value` | 400 — `BAD_TAG_FOR_ITEM`     |
| Use a non-set operator on a `Multi` tag (e.g. `==`, `LIKE`)                                | `verify_filter_conditions`     | 400 — operator not allowed for `Multi`   |
| Use `ANY`/`ALL`/`NONE`/`IS` on a non-`Multi` tag                                           | `verify_filter_conditions`     | 400 — operator not allowed for that type |
| `IS` with a wildcard element (e.g. `IS [G%]`)                                              | type resolver                  | 400 — `INVALID_FILTER_FOR_TAG_TYPE`      |
| Literal element not present in `predef_values` (and not a wildcard)                        | type resolver                  | 400 — `UNKNOWN_PREDEF_VALUE`             |
| Any list element with a wildcard whose expansion is empty in `ALL`                         | type resolver                  | Static `FALSE` — query returns 0 rows, no DB hit |

# Examples — filter to final WHERE fragment

Assume `color` is `Multi` with `predef_values = {BLUE, GREEN, GOLD, RED, YELLOW}`.

| Filter input                          | Compiled set                | Emitted WHERE fragment                                                   |
|---------------------------------------|-----------------------------|--------------------------------------------------------------------------|
| `(color ANY [GREEN, RED])`            | `{GREEN,RED}`               | `tv.value_multi && ARRAY['GREEN','RED']::text[]`                         |
| `(color ANY [G%, RED])`               | `{GOLD,GREEN,RED}`          | `tv.value_multi && ARRAY['GOLD','GREEN','RED']::text[]`                  |
| `(color ALL [G%, RED])`               | two clauses                 | `tv.value_multi && ARRAY['GOLD','GREEN'] AND tv.value_multi && ARRAY['RED']` |
| `(color NONE [DRAFT-LIKE patterns])`  | union of expansions         | `NOT (tv.value_multi && ARRAY[…]::text[])`                               |
| `(color IS [GREEN, RED])`             | `{GREEN,RED}` (canonical)   | `tv.value_multi = ARRAY['GREEN','RED']::text[]`                          |
| `(color IS [])`                       | empty set                   | `tv.value_multi = ARRAY[]::text[]`  ("untagged")                         |
| `(color ANY [Z%])`                    | `∅` — static `FALSE`        | (query short-circuits; no SQL emitted)                                   |

# Implementation surface

- `admin-server/resources/schema_cs.ddl` — `tag_definition.predef_values`,
  `tag_value.value_multi`, GIN index. Unique index kept as-is.
- `dkdto/src/web_types.rs` — `EnumTagValue::Multi`, `predef_values` on tag DTOs,
  `Multi` variant in any tag-type enum.
- `dkdto/src/error_codes.rs` — `BAD_TAG_DEFINITION`,
  `INVALID_FILTER_FOR_TAG_TYPE`, `UNKNOWN_PREDEF_VALUE`.
- `document-server/src/tag.rs` — persist & return `predef_values`; validate it
  is non-empty for `Multi` tags.
- `document-server/src/item.rs` — write-path validation + sort/dedup
  normalization on `value_multi`; read-path projection of `value_multi` into
  `TagValueElement`.
- Filter pipeline (per F0005 architecture):
  - `filter/filter_ast.rs` — `FilterValue::ValueList(Vec<String>)`; `Display`.
  - `filter/type_resolver.rs` — pattern expansion against `predef_values`;
    static short-circuits; `IS`-rejects-wildcards check.
  - `engine/generator.rs` — new arm `TagType::Multi` in
    `build_tag_value_filter`; new entries in `LEGAL_OPERATORS_BY_TAG_TYPE`.
  - Lexer/parser: list-literal syntax `[ … ]`; operator keywords `ANY`, `ALL`,
    `NONE`, `IS`.

No change to projection, preview, document text, key-manager, session-manager,
file-server, `compiled_query` cache, or the unique-row invariant on `tag_value`.

# Out of scope

- Other `multi(T)` variants (int, double, date, …) — covered by a future ticket.
- Free-form (un-bounded) text sets without `predef_values`.
- Ordering items by a `Multi` tag (`ORDER BY` on `value_multi`). Reject in
  `search_delegate` with a clear error.
- Cardinality operators (`COUNT`, `EMPTY` / `NOT_EMPTY`). Easy to add later as
  sugar over `IS []`.
- Bitmask storage for small vocabularies (≤64). A possible future
  optimization, transparent to the DSL.
