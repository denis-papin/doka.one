# Goal
Add a new tag type **`Multi`** that holds a **set of values drawn from a
predefined vocabulary**, with four set-algebra filter operators (`ANY`, `ALL`,
`NONE`, `IS`) supporting `%` wildcards. Example tag: `color` with
`predef_values = {BLUE, GREEN, RED, YELLOW}` and item values like `{RED,BLUE}`,
`{}`, `{GREEN}`. A typical filter: `(color ANY [G%, RED])`.

# Gap
`tag_definition.type` supports scalar types only (`Text`, `Int`, `Bool`,
`Double`, `Date`, `DateTime`, `Link`). There is no way to attach a *set* of
chosen-from-a-list values to an item; users wanting "topic chips", "status
flags", "color labels" have to fake it with concatenated strings or by creating
N boolean tags. The filter pipeline (`filter_ast` → `type_resolver` →
`generator`) has no list literal and no set operators. `tag_value` has no
column suitable for a set.

# Inputs
- **Tag definition (creation)**: `type = "Multi"`, plus a non-empty
  `predef_values: Vec<String>` carrying the bounded vocabulary
  (e.g. `["BLUE","GREEN","RED","YELLOW"]`).
- **Item tag value (write)**: a list of strings, each member of the tag's
  vocabulary. Order and duplicates are not significant. Empty set is allowed.
- **Filter**: `(<attribute> <op> [<elt>, <elt>, …])` where `<op>` ∈
  `{ANY, ALL, NONE, IS}` and each `<elt>` is either a literal vocabulary value
  (e.g. `RED`) or a SQL-LIKE pattern using `%` (e.g. `G%`).

# Output
- `tag_value.value_multi text[]` holds the set, **normalized** (sorted +
  deduped) at write time.
- Search SQL keeps today's JOIN-per-tag shape — one row per `(tag_id, item_id)`
  is preserved, so no `DISTINCT`, no `EXISTS`, no plan reshape. The predicate
  in the `WHERE` is one of `&&`, `@>`, `NOT (… && …)`, `=`.
- `TagValueElement` (read) exposes the set as `Vec<String>`.

| DTO + parser| New `EnumTagValue::Multi(Vec<String>)`; new `FilterValue::ValueList(Vec<String>)`; new operators `ANY`, `ALL`, `NONE`, `IS` in the lexer/parser; `predef_values` on tag DTOs | `dkdto/src/web_types.rs`, `filter/filter_ast.rs`, lexer        |
| Resolver + SQL gen | Validate operator/type pairings; expand wildcards against `predef_values` at compile time; emit one set-predicate SQL fragment per leaf | `filter/type_resolver.rs`, `engine/generator.rs`, `document-server/src/item.rs`, `document-server/src/tag.rs` |

# Rules

1. **Schema (`schema_cs.ddl`).**
   ```sql
   ALTER TABLE tag_definition ADD COLUMN predef_values text[];
   ALTER TABLE tag_value      ADD COLUMN value_multi  text[];
   CREATE INDEX tag_value_multi_gin_idx ON tag_value USING gin (value_multi);
   ```
   `value_multi` is NULL for non-`Multi` tags; `predef_values` is NULL for
   non-`Multi` tags and **NOT NULL with `array_length ≥ 1`** when
   `type = 'Multi'` (enforced in the Rust write path; no CHECK constraint).
   The unique index `tag_value_tag_item_udx (tag_id, item_id)` is **kept**: one
   row per `(tag, item)` remains the invariant.

2. **New `EnumTagValue` variant** (`dkdto/src/web_types.rs`):
   ```rust
   pub enum EnumTagValue {
       Text(Option<String>), Boolean(Option<bool>), Integer(Option<i64>),
       Double(Option<f64>), SimpleDate(Option<String>), DateTime(Option<String>),
       Link(Option<String>),
       Multi(Option<Vec<String>>),  // NEW
   }
   ```
   `TagElement` (response) gains `pub predef_values: Option<Vec<String>>`.

3. **Write-time normalization** (in `create_item_property` /
   `change_item_tag_value` in `document-server/src/item.rs`):
   - Validate every element belongs to the tag's `predef_values`; reject with
     `BAD_TAG_FOR_ITEM` otherwise.
   - Sort ascending + dedup → store the canonical form in `value_multi`.
   - This canonicalization is what makes `IS` cheap (plain `=`).

4. **Filter language additions.**
   - New value shape `FilterValue::ValueList(Vec<String>)`, syntax
     `[ELT_1, ELT_2, …]` where each `ELT` is either an unquoted literal
     vocabulary code or a double-quoted pattern containing `%`.
   - New operators `ANY`, `ALL`, `NONE`, `IS`.
   - `LEGAL_OPERATORS_BY_TAG_TYPE`: `TagType::Multi → {ANY, ALL, NONE, IS}`.
     All other types reject these operators; `Multi` rejects all other operators.

5. **Compile-time wildcard expansion** (in `type_resolver`):
   For each list element of an `ANY` / `ALL` / `NONE` clause:
   - If it contains `%` → expand against the tag's `predef_values` using
     SQL-LIKE matching, yielding a (possibly empty) subset.
   - Literals are validated against `predef_values` and pass through as a
     1-element subset.
   - `IS` does **not** accept wildcards — reject with
     `INVALID_FILTER_FOR_TAG_TYPE`.

6. **Operator → SQL mapping** (in `generator.rs::build_tag_value_filter`,
   new arm `TagType::Multi`):

   | Operator | Compile-time shape                                  | Emitted SQL fragment                                                      |
   |----------|-----------------------------------------------------|---------------------------------------------------------------------------|
   | `ANY`    | union all expansions → one set                      | `tv.value_multi && ARRAY[<set>]::text[]`                                  |
   | `NONE`   | union all expansions → one set                      | `NOT (tv.value_multi && ARRAY[<set>]::text[])`                            |
   | `ALL`    | one expansion per element (each must overlap)       | `tv.value_multi && ARRAY[<exp_1>] AND tv.value_multi && ARRAY[<exp_2>] …` |
   | `IS`     | literal set, sorted + deduped                       | `tv.value_multi = ARRAY[<set>]::text[]`                                   |

   Outer query shape is unchanged from today (single JOIN per tag).

7. **Boundary inputs — always emit a concrete predicate (no clause dropping).**
   The resolver never removes a clause or replaces the whole query with a
   constant. Every leaf emits one SQL predicate built from its compiled set,
   exactly as in Rule 6. The interesting boundaries fall straight out of those
   same predicates — only the **literal empty list `[]`** is special-cased.

   | Input                                  | Compiled set        | `ANY`                                      | `ALL`                                      | `NONE`                                          | `IS`                                |
   |----------------------------------------|---------------------|--------------------------------------------|--------------------------------------------|-------------------------------------------------|-------------------------------------|
   | Non-empty subset (literals / patterns) | `{…}`               | `value_multi && ARRAY[{…}]`                | chained `&&` per element                   | `NOT (value_multi && ARRAY[{…}])`               | `value_multi = ARRAY[{…}]`          |
   | `[%]` → full vocabulary `V`            | `{V}`               | `value_multi && ARRAY[V]` — **excludes `{}`** | chained `&&` (a `%` element → `&& ARRAY[V]`) | `NOT (value_multi && ARRAY[V])` — **only `{}`** | n/a (no wildcards)                  |
   | Pattern(s) expand to `∅` (e.g. `[Z%]`) | `{}` (from a pattern)| `value_multi && ARRAY[]::text[]` — matches nothing | `… && ARRAY[]::text[]` in the chain — matches nothing | `NOT (value_multi && ARRAY[]::text[])` — every tagged item | n/a                                 |
   | **Literal list `[]`** (special)        | `{}` (from `[]`)    | `value_multi = ARRAY[]::text[]` — **empty-set items** | `TRUE` — every tagged item (vacuous)       | `value_multi <> ARRAY[]::text[]` — non-empty items | `value_multi = ARRAY[]::text[]` — empty-set items |

   Two boundaries that used to be treated specially now need no special handling
   at all, because the ordinary predicate already does the right thing:
   - `ANY [%]` emits `value_multi && ARRAY[V]`, which overlaps every non-empty
     set and therefore **does not** return the empty-set item. (This replaces
     the old "drop clause" behaviour, which wrongly returned `{}`.)
   - A pattern that expands to `∅` (e.g. `[Z%]`) emits an overlap against the
     empty array, which PostgreSQL evaluates to `false` — so `ANY [Z%]` returns
     nothing and `NONE [Z%]` returns every tagged item, with no resolver-side
     short-circuit.

   The one deliberate special case is the **literal** empty list `[]`, read as
   the empty-set selector: `ANY []` and `IS []` both match exactly the items
   whose set is `{}`; `NONE []` matches the complement (every non-empty set);
   `ALL []` is vacuously satisfied by every tagged item. Note this makes
   `ANY []` distinct from `ANY [Z%]`: `[]` names the empty set on purpose, while
   `[Z%]` is a real overlap query that happens to match no vocabulary value.

8. **Backward compatibility.** `Text` / `Int` / `Bool` / `Double` / `Date` /
   `DateTime` / `Link` paths are untouched. The unique index on `tag_value` is
   preserved. No migration logic for existing tags. The persistence layer
   (`persist_compiled_query`) needs no change beyond the new operator strings
   appearing in the SQL text.

# Operator semantics — worked cases

Each operator compares the item's stored set (`tv.value_multi`, already
sorted + deduped at write time) against the set the filter asks for. Below,
every example uses one `Multi` tag: `color` with
`predef_values = {BLUE, GOLD, GREEN, RED, YELLOW}`.

## `ANY` — overlap: the item holds *at least one* requested value

`(color ANY [GREEN, RED])` compiles the set `{GREEN, RED}` and emits
`tv.value_multi && ARRAY['GREEN','RED']::text[]` (`&&` is Postgres array
overlap).

| Item value       | Matches? | Why                              |
|------------------|:--------:|----------------------------------|
| `{RED, BLUE}`    | ✔        | shares `RED`                     |
| `{BLUE, YELLOW}` | ✗        | no value in common               |
| `{}`             | ✗        | the empty set overlaps nothing   |

## `ALL` — superset: the item holds *every* requested value

`(color ALL [GREEN, RED])` emits one overlap term per element, joined by
`AND`: `tv.value_multi && ARRAY['GREEN'] AND tv.value_multi && ARRAY['RED']`.
The item must overlap each element separately, so it must contain all of them.

| Item value          | Matches? | Why                              |
|---------------------|:--------:|----------------------------------|
| `{GREEN, RED, BLUE}`| ✔        | holds both `GREEN` and `RED`     |
| `{GREEN, BLUE}`     | ✗        | missing `RED`                    |
| `{}`                | ✗        | holds neither                    |

## `NONE` — disjoint: the item holds *none* of the requested values

`NONE` is `ANY` negated. `(color NONE [GREEN, RED])` emits
`NOT (tv.value_multi && ARRAY['GREEN','RED']::text[])`.

| Item value       | Matches? | Why                                |
|------------------|:--------:|------------------------------------|
| `{BLUE, YELLOW}` | ✔        | shares neither `GREEN` nor `RED`   |
| `{RED}`          | ✗        | shares `RED`                       |
| `{}`             | ✔        | the empty set shares nothing       |

## `IS` — exact equality: the item's set *equals* the requested set

`IS` compares the whole set. Both sides are canonical (sorted + deduped), so
order and duplicates never matter. `(color IS [RED, GREEN])` canonicalizes to
`{GREEN, RED}` and emits `tv.value_multi = ARRAY['GREEN','RED']::text[]`.

| Item value          | Matches? | Why                                |
|---------------------|:--------:|------------------------------------|
| `{GREEN, RED}`      | ✔        | equal after normalization          |
| `{GREEN, RED, BLUE}`| ✗        | superset, not equal                |
| `{GREEN}`           | ✗        | subset, not equal                  |

`IS []` is the empty-set test: `tv.value_multi = ARRAY[]::text[]` matches only
items whose stored set is empty. Note this is a *tagged* item whose set is `{}`,
not an item that never received the tag — the latter has no `tag_value` row and
is matched by no `Multi` clause at all.

## With wildcards

A `%` element is expanded against `predef_values` at compile time, then the
same rules apply to the resulting values. With this vocabulary, `G%` expands to
`{GOLD, GREEN}`.

| Filter                  | Compiled                    | Emitted WHERE fragment                                                       |
|-------------------------|-----------------------------|------------------------------------------------------------------------------|
| `(color ANY [G%, RED])` | `{GOLD, GREEN, RED}`        | `tv.value_multi && ARRAY['GOLD','GREEN','RED']::text[]`                       |
| `(color NONE [G%])`     | `{GOLD, GREEN}`             | `NOT (tv.value_multi && ARRAY['GOLD','GREEN']::text[])`                       |
| `(color ALL [G%, RED])` | `{GOLD,GREEN}` then `{RED}` | `tv.value_multi && ARRAY['GOLD','GREEN'] AND tv.value_multi && ARRAY['RED']`  |

`ALL [G%, RED]` reads as "hold at least one G-colour **and** hold `RED`": each
list element keeps its own `&&` term, and a wildcard element is satisfied by any
one of its expansions. `IS` rejects wildcards (Rule 5).

## The two extremes: `[%]` and `[]`

The whole-vocabulary and the empty list are the two boundary inputs. Neither
drops a clause — each emits a concrete predicate (Rule 7).

| Filter        | Meaning                          | Emitted WHERE fragment                            | Empty-set item `{}` |
|---------------|----------------------------------|---------------------------------------------------|:-------------------:|
| `ANY [%]`     | item has at least one colour     | `value_multi && ARRAY[<all V>]::text[]`           | excluded            |
| `ANY []`      | item has the empty set           | `value_multi = ARRAY[]::text[]`                   | the only match      |
| `NONE [%]`    | item has no colour               | `NOT (value_multi && ARRAY[<all V>]::text[])`     | the only match      |
| `NONE []`     | item is not the empty set        | `value_multi <> ARRAY[]::text[]`                  | excluded            |

So `[%]` means "any value at all" (non-empty) and `[]` names the empty set
itself. `ANY []` and `IS []` are equivalent — both select exactly the
empty-set items. A wildcard that matches nothing (`ANY [Z%]`) is **not** the
same as `ANY []`: it emits `value_multi && ARRAY[]::text[]` and matches nothing.

# Errors

| Condition                                                                                  | Stage that rejects             | Outcome                                  |
|--------------------------------------------------------------------------------------------|--------------------------------|------------------------------------------|
| Create a `Multi` tag with empty/missing `predef_values`                                    | `add_tag` (`tag.rs:356`)       | 400 — `BAD_TAG_DEFINITION`               |
| Write a `value_multi` containing a value outside `predef_values`                           | `create_item_property` / `change_item_tag_value` | 400 — `BAD_TAG_FOR_ITEM`     |
| Use a non-set operator on a `Multi` tag (e.g. `==`, `LIKE`)                                | `verify_filter_conditions`     | 400 — operator not allowed for `Multi`   |
| Use `ANY`/`ALL`/`NONE`/`IS` on a non-`Multi` tag                                           | `verify_filter_conditions`     | 400 — operator not allowed for that type |
| `IS` with a wildcard element (e.g. `IS [G%]`)                                              | type resolver                  | 400 — `INVALID_FILTER_FOR_TAG_TYPE`      |
| Literal element not present in `predef_values` (and not a wildcard)                        | type resolver                  | 400 — `UNKNOWN_PREDEF_VALUE`             |
| A wildcard element whose expansion is empty (e.g. `ANY [Z%]`)                              | not an error                   | emits `value_multi && ARRAY[]::text[]` → 0 rows (Rule 7) |

# Examples — filter to final WHERE fragment

Assume `color` is `Multi` with `predef_values = {BLUE, GREEN, GOLD, RED, YELLOW}`.

| Filter input                          | Compiled set                | Emitted WHERE fragment                                                   |
|---------------------------------------|-----------------------------|--------------------------------------------------------------------------|
| `(color ANY [GREEN, RED])`            | `{GREEN,RED}`               | `tv.value_multi && ARRAY['GREEN','RED']::text[]`                         |
| `(color ANY [G%, RED])`               | `{GOLD,GREEN,RED}`          | `tv.value_multi && ARRAY['GOLD','GREEN','RED']::text[]`                  |
| `(color ALL [G%, RED])`               | two clauses                 | `tv.value_multi && ARRAY['GOLD','GREEN'] AND tv.value_multi && ARRAY['RED']` |
| `(color NONE [G%, RED])`              | `{GOLD,GREEN,RED}`          | `NOT (tv.value_multi && ARRAY['GOLD','GREEN','RED']::text[])`            |
| `(color IS [GREEN, RED])`             | `{GREEN,RED}` (canonical)   | `tv.value_multi = ARRAY['GREEN','RED']::text[]`                          |
| `(color ANY [%])`                     | `{BLUE,GOLD,GREEN,RED,YELLOW}` (full `V`) | `tv.value_multi && ARRAY['BLUE','GOLD','GREEN','RED','YELLOW']::text[]` — non-empty items, excludes `{}` |
| `(color ANY [Z%])`                    | `{}` (pattern matched nothing) | `tv.value_multi && ARRAY[]::text[]` — matches nothing                 |
| `(color ANY [])`                      | empty-set selector          | `tv.value_multi = ARRAY[]::text[]` — empty-set items (same as `IS []`)   |
| `(color IS [])`                       | empty-set selector          | `tv.value_multi = ARRAY[]::text[]` — empty-set items                     |
| `(color NONE [])`                     | empty-set selector          | `tv.value_multi <> ARRAY[]::text[]` — non-empty items                    |

Every WHERE fragment above is validated as real PostgreSQL — the columns, the
GIN index, the `&&` / `=` array predicates, and the full JOIN-per-condition
query shape — by [validate_multi_sql.sql](./validate_multi_sql.sql). It is a
self-contained sandbox (creates a throwaway `f0007_validate` schema, seeds
items, runs one complete query per operator with the expected row ids, and
drops itself). Run it to confirm the target SQL before building the DSL
compilation chain:

```bash
psql -f _ai/F0007-tag-multi-value/validate_multi_sql.sql "postgresql://user:pwd@host:5432/db"
```

# Implementation surface

- `admin-server/resources/schema_cs.ddl` — `tag_definition.predef_values`,
  `tag_value.value_multi`, GIN index. Unique index kept as-is.
- `dkdto/src/web_types.rs` — `EnumTagValue::Multi`, `predef_values` on tag DTOs,
  `Multi` variant in any tag-type enum.
- `dkdto/src/error_codes.rs` — `BAD_TAG_DEFINITION`,
  `INVALID_FILTER_FOR_TAG_TYPE`, `UNKNOWN_PREDEF_VALUE`.
- `document-server/src/tag.rs` — persist & return `predef_values`; validate it
  is non-empty for `Multi` tags.
- `document-server/src/item.rs` — write-path validation + sort/dedup
  normalization on `value_multi`; read-path projection of `value_multi` into
  `TagValueElement`.
- Filter pipeline (per F0005 architecture):
  - `filter/filter_ast.rs` — `FilterValue::ValueList(Vec<String>)`; `Display`.
  - `filter/type_resolver.rs` — pattern expansion against `predef_values`;
    literal-`[]` empty-set handling (Rule 7); `IS`-rejects-wildcards check.
  - `engine/generator.rs` — new arm `TagType::Multi` in
    `build_tag_value_filter`; new entries in `LEGAL_OPERATORS_BY_TAG_TYPE`.
  - Lexer/parser: list-literal syntax `[ … ]`; operator keywords `ANY`, `ALL`,
    `NONE`, `IS`.

No change to projection, preview, document text, key-manager, session-manager,
file-server, `compiled_query` cache, or the unique-row invariant on `tag_value`.

# Out of scope

- Other `multi(T)` variants (int, double, date, …) — covered by a future ticket.
- Free-form (un-bounded) text sets without `predef_values`.
- Ordering items by a `Multi` tag (`ORDER BY` on `value_multi`). Reject in
  `search_delegate` with a clear error.
- Cardinality operators (`COUNT`, `EMPTY` / `NOT_EMPTY`). Easy to add later as
  sugar over `IS []`.
- Bitmask storage for small vocabularies (≤64). A possible future
  optimization, transparent to the DSL.

End-to-end black-box validation lives in
[integration_test_tag_multi_value.md](./integration_test_tag_multi_value.md)

`doka-api-tests/tests/F0007-tag-multi-value.rs`. Fixtures are defined once as

create a `Multi` tag with a vocabulary; write/read an item with empty set,
single value, multi value (with sort + dedup); filter with each of `ANY`,
`ALL`, `NONE`, `IS` — literals only; the same operators with `%` wildcards
(including patterns that expand to `∅` and to the full vocabulary); the literal
empty list `[]` per operator (`ANY []`/`IS []` → empty set, `NONE []` →
non-empty, `ALL []` → all tagged); the "empty set vs untagged" distinction
(a `{}` tag row matches, a never-tagged item never does); a second `Multi` tag
(`module` = {BACKEND, FRONTEND}) used on its own and combined with `color`
under `AND`; a `Multi` tag combined with a scalar (`Int`) tag; reject writes
with off-vocabulary values; reject `IS [G%]`; reject an unknown literal; reject
`==` on a `Multi` tag; reject `ANY` on a `Text` tag.
